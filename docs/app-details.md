# Grant+ Operating Details

## Funder Hub — รุ่น 5 พฤศจิกายน 2569

ทางเข้าปัจจุบันคือ `/funder`, `/researcher`, `/collaboration` และ Admin แยกเดิม `/private-sector` ส่งต่อไป `/funder` Funder Hub รวมผู้ให้ทุนรัฐและเอกชน พร้อมคงโจทย์/เงินร่วมทุน/Marketplace

| ข้อมูล | ความหมาย |
| --- | --- |
| ผู้ให้ทุนตัวอย่าง 6 แห่ง | รัฐ 4 และเอกชน 2 ชื่อหน่วยงานจริงใช้เป็นบริบทสาธิต ไม่ใช่การรับรองหรือรายงานการจัดสรรจริง |
| งานวิจัย 14 ระเบียน | โครงการที่จัดสรรแล้ว ปี 2569–2570 พร้อมผู้วิจัยหลัก สาขา ผู้ให้ทุน และยุทธศาสตร์หลัก |
| นักวิจัย 10 ราย | บุคคล/ประวัติสมมติใน 6 หมวดสาขาของต้นแบบ ไม่ใช่ทะเบียนนักวิจัยที่เชื่อมจริง |
| สัญญาตั้งต้น 10 ฉบับ | หนึ่งโครงการมีหนึ่งสัญญา ผู้รับทุนรายเดียวมีหลายสัญญาได้ |
| งวดสัญญา | จำนวนเงิน วันครบกำหนด รอเบิกจ่าย/เบิกจ่ายแล้ว วันที่และเลขอ้างอิงจำลอง |

จำนวนทุน = จำนวนโครงการในตัวกรอง งบจัดสรร = ผลรวมวงเงินโครงการ สัดส่วนยุทธศาสตร์ = วงเงินด้านนั้น ÷ งบจัดสรรในตัวกรอง × 100 แต่ละโครงการนับด้านหลักเดียวจึงไม่ซ้ำ ยอดเบิกจ่ายรวมเฉพาะงวดที่จ่ายแล้วของโครงการในตัวกรอง งบที่ยังไม่เบิกจ่ายรวมโครงการที่ยังไม่ทำสัญญาด้วย

ฐานสาธิตตั้งต้นมีวงเงิน 24,100,000 บาท เบิกจ่าย 7,300,000 บาท เป็นข้อมูลสมมติทั้งหมด บันทึกงวดเพิ่มยอดเบิกจ่ายแต่ไม่เพิ่มวงเงินจัดสรร

สัญญาต้องมีเลขไม่ซ้ำ ยอดทุกงวดรวมเท่ากับวงเงินจัดสรร วันครบกำหนดอยู่ในช่วงสัญญา จำนวนเงินเป็นบาทเต็มมากกว่า 0 และ 1–12 งวด งวดที่จ่ายแล้วคงข้อมูลและหลักฐานเดิม ห้ามจ่ายซ้ำ การบันทึกใช้เต็มงวด ไม่รองรับจ่ายบางส่วนหรือโอนเงินจริง

`fundingContracts` ใน root demo snapshot เก็บสัญญา/การจ่าย คงอยู่ขณะเปลี่ยนเมนูและ logout/เข้า Hub ในแท็บเดิม รีเฟรชเต็มหน้าจะกลับค่าตั้งต้น ทุกโมดูลต้อง merge snapshot เพื่อไม่ล้างข้อมูลอื่น ไม่มี schema หรือ migration เพิ่ม

ข้อมูลอยู่ใน `src/data/funder-demo-data.ts` ชนิดข้อมูล `src/types/funder.ts` การคำนวณ/ตรวจสอบ `src/lib/funder-portfolio.ts` ชื่อยุทธศาสตร์อ้างอิง [เอกสารยุทธศาสตร์ชาติ](https://mhesi.nrct.go.th/archives/s/mhesi_archives/item/1288) การจัดหมวดโครงการเป็นสมมติฐานสาธิต

## Mode And Storage Rules

- `Simulation mode` เริ่มด้วยข้อมูลตัวอย่างและเก็บการเปลี่ยนแปลงไว้เฉพาะระหว่างเปิดหน้า
- `โหมดกรอกและบันทึกข้อมูล` เก็บโปรไฟล์ ร่าง รายการใบสมัคร และตำแหน่งขั้นตอนจำลองใน PostgreSQL ของ Neon ผ่าน API ฝั่งเซิร์ฟเวอร์
- ตาราง `grant_users`, `grant_sessions` และ `grant_applications` แยกโปรไฟล์, session ที่ hash แล้ว และใบสมัครตามเจ้าของข้อมูล
- cookie `grant_plus_session` เป็น HttpOnly, SameSite=Lax, Secure เมื่อรัน production และหมดอายุใน 30 วัน ใช้เปิดทางให้กรอกอีเมลอย่างเดียวบนอุปกรณ์เดิม
- ปุ่ม “ออกจากระบบ” เก็บ cookie ไว้เพื่อความสะดวก; ปุ่ม “ลืมอุปกรณ์นี้” ลบ session ฝั่งฐานข้อมูลและล้าง cookie
- ระบบยังไม่มีการแบ่งสิทธิ์เจ้าหน้าที่, audit trail, account recovery, retention policy หรือ backup policy ที่ผ่านการรับรอง
- การเลือกไฟล์บันทึกเฉพาะชื่อไฟล์ในร่าง ไฟล์จริงยังไม่ถูกอัปโหลดหรือจัดเก็บ
- รหัสที่ขึ้นต้น `SIM-` และสถานะหลังส่งเป็นผลลัพธ์จำลอง ไม่ใช่เลขรับเรื่องจากหน่วยงาน

## Simulated Application Journey

1. กรอกและบันทึกข้อมูล — บันทึกในฐานข้อมูลจริงเฉพาะในโหมดกรอกข้อมูล
2. ส่งต่อแหล่งทุน — Simulation
3. ตรวจคุณสมบัติและเอกสาร — Simulation
4. ผู้ทรงคุณวุฒิประเมิน — Simulation
5. คณะกรรมการพิจารณา — Simulation
6. ประกาศผลและทำสัญญา — Simulation

## Readiness Calculation

- “ครบ” คิด 1 คะแนน “มีบางส่วน” คิด 0.5 คะแนน และ “ยังไม่พบ” คิด 0 คะแนน
- เปอร์เซ็นต์เป็นตัวชี้ความครบของข้อเสนอเทียบกับ template ที่เลือก ไม่ใช่โอกาสได้รับทุน
- รายการสาธิตมีแม่แบบ วช. Strategic Fund, NIA Open Innovation และ บพข. Full Proposal
- แหล่งอ้างอิงใน prototype ใช้หน้าคู่มือ/ประกาศของ NRIIS, NIA และ บพข.; ก่อนใช้งานจริงต้องให้เจ้าของทุนตรวจและอัปเดตรุ่นแม่แบบ
