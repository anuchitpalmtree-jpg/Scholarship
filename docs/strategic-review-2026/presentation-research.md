- Private Sector Hub: ประกาศโจทย์ ค้นนักวิจัยหรือแล็บที่เกี่ยวข้อง และ Tech Marketplace ที่มีระดับ TRL กับประเด็น Licensing

สไลด์ User Journey, Architecture และ Demo ต้องใช้การแบ่งพื้นที่นี้แทนการรวมทุกโมดูลไว้ในเมนูผู้วิจัยเดียวกัน หน้า 5 “เส้นทางเริ่มต้นสองแบบ” ควรอธิบายสองฝั่งที่เข้ามาใช้บริการและพื้นที่ Collaboration ร่วมกัน โดยแสดง 3 ทางเลือกที่หน้าเข้าสู่ระบบ ส่วน Admin อยู่ด้านสนับสนุนหลังบ้าน

ขอบเขตสาธิต: การเลือก Hub เป็นการแยกหน้าจอและลำดับงาน การเข้าสู่ Admin และสลับบทบาทยังจำลอง ไม่มีการตรวจคำเชิญเข้าห้องหรือสิทธิ์ฝั่งเซิร์ฟเวอร์ ห้องโครงการไม่ใช่ Secure Workspace ที่ใช้ข้อมูลลับได้จริง การแนบไฟล์เก็บชื่อไฟล์ การประชุมไม่เปิดวิดีโอจริง ร่างสัญญาไม่มีผลลงนาม และการตรวจรับงวดไม่โอนเงินหรืออนุมัติเบิกจ่าย

**บนสไลด์:** นักวิจัยกำหนดความเชี่ยวชาญ / ระบบแนะนำโจทย์ที่เกี่ยวข้อง / เปิดดูเหตุผลการจับคู่ / นักวิจัยแสดงความสนใจและควบคุมการแจ้งเตือน

**บทพูด:** แสดงการแจ้งเตือนในแอปด้วยข้อมูลจำลอง อีเมลหรือช่องทางภายนอกจะเชื่อมจริงหลังตกลงสิทธิ์และความยินยอม ไม่กล่าวว่าได้ส่งอีเมลออกไปแล้ว

### 10. AI Smart Match และการตรวจความครบ

**บนสไลด์:** ค้นทุนจากคำอธิบายโครงการ / ตรวจหัวข้อและเอกสารตามแม่แบบทุน / ผู้ยื่นเลือกข้อมูลเดิมและผู้ประสานงาน / แก้รายการที่ยังไม่ครบ

**ข้อความกำกับ:** ตรวจความครบตามแม่แบบ ไม่ให้คะแนนคุณภาพงานหรือโอกาสได้รับทุน

**บทพูด:** คงเส้นทางเดิมและเงื่อนไขแต่ละทุน ผู้เชี่ยวชาญของแหล่งทุนเป็นผู้ทบทวนเนื้อหาทางวิชาการ ตัวเลขความครบไม่ใช่คะแนนความดีของโครงการ

### 11. การตรวจความคล้ายเชิงสาระ

**บนสไลด์:** วัตถุประสงค์และปัญหาวิจัย / วิธีวิจัยและข้อมูล / ผลผลิตและกลุ่มเป้าหมาย / ข้อความอ้างอิงที่นำมาเทียบและข้อจำกัดของผล

**เป้าหมายเทคนิค:** Deep Semantic Text Analysis ใช้ข้อความหลายส่วนร่วมกัน ไม่อาศัยหมวดหมู่หรือคีย์เวิร์ดเพียงอย่างเดียว

**บทพูด:** ในต้นแบบให้ดูรายงานตัวอย่างพร้อมเหตุผลและแหล่งข้อมูลจำลอง ยังไม่อ้างว่ารัน deep semantic model ที่ผ่านการประเมินหรือเชื่อมข้อเสนอทุกแหล่งทุนแล้ว ระยะพัฒนาต้องมีชุดทดสอบภาษาไทยและผู้เชี่ยวชาญประเมิน false positive/negative

### 12. คำเตือนและ Human-in-the-Loop

**บนสไลด์:** ระบบแสดงคู่ข้อเสนอและเหตุผล / ผู้ยื่นรับทราบและชี้แจง / เจ้าหน้าที่ตรวจหลักฐาน / คณะกรรมการผู้มีอำนาจพิจารณา

**ข้อความเด่น:** ความคล้ายเป็นสัญญาณให้ตรวจสอบ ผู้ยื่นรับทราบแล้วส่งต่อได้

**บทพูด:** งานต่อยอดอาจมีเหตุผลชอบด้วยเกณฑ์ ไม่ใช้เปอร์เซ็นต์ความคล้ายเป็นข้อสรุปว่าทุจริตหรืองานซ้ำ ให้ช่องชี้แจงและบันทึกเหตุผลการตัดสินของคน

### 13. ยืนยันส่งและติดตามสถานะ

**บนสไลด์:** แบบฟอร์ม auto-fill ตัวอย่าง / เลขรับเรื่องจำลอง / อีเมลตัวอย่าง / สถานะรับเรื่อง ตรวจเอกสาร และรอพิจารณา

### 15. Prototype และ Impact Tracking

**บนสไลด์:** เป้าหมายต้นแบบและ milestone / ค่าตั้งต้น / เป้าหมาย / ผลรายงานจริงพร้อมวันและหลักฐาน / ผู้ตรวจรับหรือผู้รับรองผล

**บทพูด:** แยกผลผลิต เช่น ต้นแบบ ออกจากผลลัพธ์ เช่น หน่วยงานนำไปใช้ และผลกระทบ เช่น ต้นทุนหรือผลต่อชุมชน หน้าจอสาธิตใช้ข้อมูลตัวอย่าง ไม่แปลเป็นผลสำเร็จของ Grant+

### 16. เส้นทางสาธิตครบ 5 ด้าน

**ลำดับสาธิต:** เปิดข่าวทุน / เปิดโจทย์บริษัทและสร้างโจทย์ตัวอย่าง / ปรับส่วนร่วมทุน / เข้าบทบาทนักวิจัยและดูโจทย์แจ้งเตือน / Smart Match และ Pre-check / รับทราบความคล้ายและส่ง / เปิดสถานะ / แสดงความสนใจใน Marketplace / อัปเดตผล milestone / เปิดมาตรฐานข้อมูลและเปรียบเทียบต้นทุน

**ผังแก้ไขได้:** ผู้ยื่นและภาคอุตสาหกรรม / Grant+ workflow / สัญญาข้อมูลกลางและตัวแปลงข้อมูลของหน่วยงาน / ระบบรับเรื่องและพิจารณาของเจ้าของทุน / ข้อมูลติดตามผลตามสิทธิ์

### 18. มาตรฐานข้อมูลกลางที่เสนอ

**บนสไลด์:** รหัสทุนและเวอร์ชันประกาศ / รหัสข้อเสนอและหน่วยงาน / ผู้มีสิทธิ์และผู้ยื่นแทน / โครงแม่แบบและสถานะ / เวลารับเรื่องและประวัติเปลี่ยนแปลง / รายการผลผลิตและตัวชี้วัด

**ข้อเสนอ:** OpenAPI สำหรับอธิบาย API ร่วมกับ schema รหัสอ้างอิง การกำหนดสิทธิ์ และการจัดการเวอร์ชัน

**บทพูด:** OpenAPI ช่วยให้คู่เชื่อมเข้าใจข้อกำหนดตรงกัน แต่ไม่ทำให้ข้อมูล ระบบสิทธิ์ และกระบวนงานทุกหน่วยงานตรงกันโดยอัตโนมัติ ต้องร่วมออกแบบกับหน่วยงานเจ้าของข้อมูลและหน่วยงานนโยบาย ไม่กล่าวว่าเป็นมาตรฐานชาติที่ประกาศใช้แล้ว

### 19. การลดต้นทุนเชื่อมต่อและการใช้ AI

**บนสไลด์:** ใช้ schema/adapter ที่นำกลับมาใช้ได้ / ทดสอบสัญญาข้อมูลและติดตามเวอร์ชัน / ประมวลผลเฉพาะส่วนที่จำเป็น / เก็บ cache ตามสิทธิ์และอายุข้อมูล / กำหนดวงเงินและติดตามค่าใช้จ่ายต่อคำขอ

### 23. ตัวชี้วัดที่ต้องเก็บจริง

**บริการทุน:** เวลาจัดเตรียมค่ามัธยฐาน เป้าหมายเดิมลดลงอย่างน้อย30% / อัตราคืนเพราะเอกสารไม่ครบ เป้าหมายเดิมลดลง20%แบบสัมพัทธ์

**Corporate Track:** จำนวนโจทย์ที่มีผู้รับผิดชอบ จำนวนคู่ที่เข้าสู่การหารือ สัดส่วนโครงการที่มีหลักฐานผู้ใช้ประโยชน์

**Semanticและธรรมาภิบาล:** ความครบของหลักฐาน จำนวนเตือนผิด/พลาดตามชุดทดสอบ ระยะเวลาทบทวนและการชี้แจง

**ต้นทุน:** ค่าเชื่อมต่อที่เกิดจริง ค่าใช้จ่ายต่อคำขอ ค่าใช้จ่ายดูแลเมื่อมาตรฐานเปลี่ยน

**บนสไลด์:** เจ้าของทุนรับรองแม่แบบและพิจารณาทุน / เจ้าของบริการดูแลสิทธิ์ ความปลอดภัยและเหตุขัดข้อง / บริษัทรับผิดชอบโจทย์และเงื่อนไขข้อมูล / นักวิจัยและผู้ยื่นยืนยันข้อมูลและสิทธิ์ / เจ้าของผลงานรับรองข้อมูลIPและการเปิดเผย

**เกณฑ์ก่อนใช้จริง:** ตัวตนและมอบสิทธิ์ / ที่เก็บไฟล์ / การเข้าถึง / audit / ความเป็นส่วนตัว / ข้อตกลงข้อมูล / กระบวนการพิจารณาและอุทธรณ์ของหน่วยงาน

**บทพูด:** แม้ต้นแบบมีการบันทึกสถานะหรือข้อมูลได้ ก็ยังไม่เท่ากับผ่านความพร้อมสำหรับข้อมูลส่วนบุคคลจริง AIต้องมีเจ้าของกระบวนงานและคนทบทวนผลที่มีผลต่อผู้ยื่น

### 25. ข้อเสนอเพื่อการสนับสนุน

**บนสไลด์:** เห็นชอบแนวทางครบ5ด้าน / ประสานเจ้าภาพแหล่งทุนและตัวแทนอุตสาหกรรม / ร่วมรับรองแม่แบบและขอบเขตข้อมูล / ทบทวนกรอบเดิม56.1ล้านบาทจากงานและต้นทุนจริงก่อนจัดทำคำของบอย่างเป็นทางการ

**บทพูด:** ขอให้การประชุมกลุ่มตกลงขอบเขต ผู้รับผิดชอบ และเส้นทางนำร่อง การอนุมัติทุนวิจัยและงบพัฒนาระบบยังเป็นอำนาจหน่วยงานตามกระบวนงานเดิม จบด้วยทุนที่ใช่ไปได้ไกลกว่า

### 26. แหล่งข้อมูลและสถานะต้นแบบ

**แหล่งภายใน:** PDFนำเสนอ4พฤศจิกายน2569 / Investment Modelและรายงานทบทวน4พฤศจิกายน / ข้อคิดเห็นผู้ทรงคุณวุฒิที่ผู้ใช้ส่ง5พฤศจิกายน / ภาพหน้าจอจากต้นแบบรุ่นปรับ

**แหล่งภายนอกสำหรับตรวจต่อ:** คู่มือNRIIS `https://nriis.go.th/Manual.aspx` / บริการทุนNIA `https://www.nia.or.th/service/financial-support` / OpenAPI `https://spec.openapis.org/oas/latest.html`

**ต้นแบบเดิม:** `https://govfund-match.vercel.app/` ให้แทนด้วยURLรุ่นที่ปรับและตรวจแล้วเมื่อส่งมอบ

**ข้อความกำกับ:** ข้อมูลบริษัท โจทย์ นักวิจัย การเชื่อมต่อ และผลAIเป็นข้อมูลสาธิต ไม่มีผลใช้งานจริงที่ยืนยัน ระยะถัดไปต้องทำข้อตกลงและทดสอบกับเจ้าภาพ

## รายการตรวจความสอดคล้องก่อนส่ง

- ภาพหน้าจอใหม่ทุกหน้าใช้รุ่นเดียวกับระบบที่เปิดสาธิตได้
- จำนวนสไลด์และเลขหน้าต้องตรงกันทุกหน้า ไม่คงเลขซ้ำจากไฟล์เก่า
- ทุกคำว่า “อนุมัติ” ระบุผู้มีอำนาจของแหล่งทุน ห้ามใช้สถานะAIอนุมัติ
- ลิงก์หรือไฟล์OpenAPIต้องเปิดได้จริง หากมีปุ่มดาวน์โหลดมาตรฐานข้อมูล
- ไม่ติดป้ายDeepSemanticที่ทำให้เข้าใจว่าเป็นโมเดลจริง หากระบบแสดงผลจำลองหรือเหตุผลตัวอย่าง
- การโพสต์โจทย์ต้องทำให้รายการและการแจ้งเตือนที่เกี่ยวข้องเปลี่ยนตามพฤติกรรมสาธิต ไม่ใช่ปุ่มนิ่ง
- Calculatorแสดงหน่วยบาท สัดส่วน เพดาน และความแตกต่างระหว่างค่าป้อนกับเกณฑ์แหล่งทุนจริง
- Marketplaceต้องแสดงความสนใจได้ โดยไม่อ้างว่าส่งสัญญาผูกพันหรือโอนสิทธิ์แล้ว
- Impactแยกค่าตั้งต้น เป้าหมาย และผลรายงาน พร้อมสถานะหลักฐาน
- งบเดิมไม่เท่ากับงบใหม่ที่ผ่านการปรับแล้ว และSROIเดิมไม่ใช่ผลหลังเพิ่มโมดูล
- ห้ามเรียก33.6ล้านบาทว่าค่าAPIปีแรกโดยไม่มีการยืนยันจากเจ้าของแบบจำลอง
